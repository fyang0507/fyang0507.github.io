WHAT CHANGED FROM ROUND 2
DYou can’t display the dotted dissolve initially, it should only appear when scrolling. I think this is a bug in the display page, I don’t think you mean it.

Root cause: the halftone wedge had a fixed depth. It was anchored to the paper edge, and at the top of the page that edge is already inside the window, so the wedge was printed before any scroll. Only its position followed the scroll, never its amount. Fix: the wedge now has a depth D(y) that is part of the scroll mapping. At y = 0, D = 0: the clean cover image, ending in one smooth hand-cut paper edge, with no dots anywhere. The first pixels you scroll add halftone one for one, easing to the full 200px by y = 400 (150px by 300 on a phone), which is before the paper lands. From then on the page is round 2 exactly. Scroll back to the top and D returns to 0, and the cover is clean again. Reduced motion never prints dots. The paper edge is now drawn as one path, not cell by cell, so the clean state has no staircase.

THE LAYOUT PLAN · 版式数字

Hero height, the body’s top padding and the nav’s height change are one plan, not three settings. The intro’s bottom padding is gap + Z + pad, so the body starts exactly pad below solid paper. The paper edge moves with the text, so that distance holds at every scroll position. It reaches the top of the window at sL = B0 − pad. At that moment the first line sits at pad = n1 + 28, just as the nav settles to n1. New in round 3: the halftone’s depth is D(y) = Z · (1 − (1 − y/R)²) with R = min(2Z, sL). It starts at 0, grows one for one at first, and reaches Z before the landing.

RECOMMENDATION

Ship A and D together as the Reading page, with the round-3 fix. The print-over is now truly the one dense event, and it belongs to the reader. The page opens on the whole cover. The halftone appears only because you began to read, deepens as you go, and hands over to the paper, the nav and the pen in the margin. After that the page stays quiet, with a graphite line and one coral loop. Going back to the top restores the cover, because the state is a function of the scroll and nothing else.

Watch three things in production, as in round 2. First, the halftone samples the cover through a canvas, so covers must stay same-origin (they are, in images/derived/). Second, dark photographic covers print heavier dots, so check new covers at the first few hundred pixels of scroll. Third, the rail needs about 180px of left margin, so below roughly 1000px wide it becomes the phone strip. One more for the port: keep D(0) = 0 as an invariant with a test. A reload that restores the scroll mid-hero will show the dissolve for that position, which is correct.
